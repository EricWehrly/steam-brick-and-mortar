# 2026-04-18

## Branch: `openclaw/feat-texture-placement-split` → merged

### Prefetch/place race condition (major fix)
- Diagnosed via console log: `GamesSort` fired before `prefetchArtwork()` promises resolved, causing all 800+ games to miss the atlas and fall through to label boxes instead of artwork.
- Implemented rendezvous pattern in `GameBoxSpawner`: each game places itself when both conditions are met — prefetch settled AND placement intent assigned — whichever arrives last.
- Promise references not stored past `.then()` attachment; games trickle in naturally.
- Probe tests confirm both orderings (intent before prefetch, prefetch before intent).

### Architecture cleanup
- `GpuGameBoxRenderer.placeGame()` — unified placement (try artwork, fall through to label). Artwork/label fork moved from spawner to renderer.
- `side` param eliminated from `placeGame`, `placeLabelBox`, `addLabelInstance` — rotation quaternion already encodes front/back via `calculateGameRotation`.
- `IGameBoxRenderer` deleted (no remaining references), `createBatchGameBoxes` removed.
- `LodDistanceManager` ownership moved from `GpuGameBoxRenderer` to `LodArtworkOrchestratorDebug`.
- `fromAppSettings()` factory and CDN ceiling config moved to `LodArtworkOrchestrator` base class (not debug subclass — debug is for dev instrumentation only).
- `buildAppSettingsConfig()` extracted as protected static helper for subclass override.
- Vestigial `maxGames` field removed from debug subclass (`maxTextures` already does this).
- `placeArtworkInstance` removed (dead after rendezvous refactor).

### Label re-sort fix
- `InstancedLabelRenderer.clear()` was clearing `gameNameToTextureIndex`, causing re-sort to re-bake all label textures and immediately exhaust the 103-slot limit. Fix: retain the map on clear so existing texture slots are reused.

### Signs on re-sort
- Pre-existing bug, not caused by this branch. `shelfBucketKey()` returns null for `by-rating` and `by-genre` sort modes. Separate branch needed.
